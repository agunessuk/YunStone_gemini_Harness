# 상태 보고

FOD-skills `evidence-status-report`를 줄이고, 이 사용자가 실제로 불만을 말한 지점("너가 뭘 했다는건지 알 수가 없어", "지금 나에게 어떤 작업을 요청한거야? 한국어로 설명해봐")을 반영했다.

## 순서
1. 답하기 전에 지금 상태를 확인한다: 산출물 존재와 수정 시각, 프로세스 생존, 로그 마지막 줄, 테스트 출력. 기억으로 답하지 않는다.
2. 항목마다 상태를 단다: **확인함**(근거), **미확인**(무엇을 보면 확인되는지), **실패**(증상).
3. 사용자에게 무언가를 요청하는 중이면 그것을 맨 위에 쉬운 말로 쓴다: 무엇을, 왜, 어디서.

## 형식
| 항목 | 상태 | 근거 / 확인 방법 |
|---|---|---|
| 원소술사 아이콘 24개 적용 | 확인함 | 리소스팩에 24개, 빌드 성공 |
| 인게임 표시 | 미확인 | 서버를 열어 `/classpack skills`로 확인 필요 |

- 표 아래: 다음 행동 한 줄, 사용자가 할 일 한 줄(있을 때만).
- 내부 이름(J02a, CapKey)은 쓰더라도 옆에 무엇인지 풀어 쓴다.
- 하위 에이전트 보고를 옮긴 항목은 "에이전트 보고, 직접 미확인"으로 표시한다.

## 하지 않는 것
- "아마 됐을 것", "정상으로 보임"처럼 확인 없는 완료를 쓰지 않는다.
- 시간 제한으로 끊긴 실행을 통과로 쓰지 않는다.
- 긴 로그를 붙이지 않는다. 핵심 한두 줄만.
