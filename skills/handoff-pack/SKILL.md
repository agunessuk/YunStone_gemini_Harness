# 인계 패키지 만들기

FOD-skills `cross-device-handoff`, `delegation-loop`을 이 사용자의 방식(AI 간 잦은 인계, 토큰 절약, 원본 보존)에 맞게 고쳤다.

## 언제
- 다른 AI에게 작업을 넘길 때, 새 채팅에서 이어갈 때
- 다른 서버·PC에서 실행할 수 있는 배포본을 만들 때
- 팀 저장소에 올릴 통합본을 만들 때

## 먼저 정할 것 (요청에 없으면 기본값)
| 항목 | 기본값 |
|---|---|
| 받는 쪽 | 이전 대화를 전혀 모르는 AI |
| 변경 이력 | 넣지 않는다. 무엇을 바꿨는지는 md 요약으로만 |
| 실행 파일 | 받는 쪽에서 바로 실행할 수 있게 실행에 필요한 것은 모두 넣는다 |
| 위치 | 프로젝트의 `handoff/` (하네스 표준). 만든 `.zip`은 보호되므로 고칠 일이 있으면 새 이름으로 만든다(`이름_vN_YYYYMMDD.zip`) |

## 패키지 구성
```
<이름>_vN/
├─ START_HERE.md      # 받는 쪽이 가장 먼저 읽을 파일
├─ MANIFEST.json      # 파일 목록, 크기, sha256, 버전, 만든 날짜
├─ PROMPT_첫작업.md   # 받는 AI에게 그대로 붙여넣을 첫 지시
├─ src/ …            # 작업 대상 (폴더마다 README 한 개)
└─ docs/
   ├─ 현재상태.md     # 끝난 것, 진행 중인 것, 막힌 것, 미확인
   └─ 결정기록.md     # 확정된 결정과 이유 (다시 묻지 않게)
```

## START_HERE.md 내용
1. 이 패키지가 무엇인지 한 줄
2. **대전제**: 바꾸면 안 되는 것, 범위, 품질 기준
3. 폴더 지도: 폴더마다 한 줄 설명과 먼저 볼 파일 (토큰을 아끼게 요약을 충실히)
4. 실행·빌드·확인 명령 한 줄씩과 기대 결과
5. 다음 할 일, 우선순위 순서

## PROMPT_첫작업.md 형식
- 첫 줄: "너는 이전 대화를 모른다. 첨부 파일과 이 지시를 기준으로 시작해라. 첨부를 확인하기 전에 이전 작업을 기억한다고 말하지 마라."
- 역할, 목표, 이번 단계에서 할 것과 하지 않을 것(예: "아직 코드 수정은 하지 마라")
- 읽는 순서
- 끝났다고 볼 기준(파일 경로·개수·수치)
- 보고 형식
- 원격·모바일 환경에서도 볼 수 있게 이 프롬프트는 **채팅 본문에도 텍스트로** 붙여 준다.

## 순서
1. 넣을 것과 뺄 것 목록을 먼저 만든다. 빌드 산출물, 로그, 해시 파일, 미리보기, 이전 버전, 더미 파일은 기본으로 뺀다.
2. 새 작업 폴더에 복사해 조립한다. 원래 작업 폴더에서 지우지 않는다.
3. 비밀값(.env, 키, 토큰)이 들어가지 않았는지 검색한다.
4. 압축 후 **압축을 새 폴더에 풀어** START_HERE의 실행 명령이 실제로 되는지 확인한다. 못 했으면 미확인으로 적는다.
5. 패키지 경로, 크기, 확인 결과를 보고하고 파일을 직접 보낸다.

## 받는 쪽이 사람일 때
- 해시·로그 파일이 왜 있는지, 풀고 나서 지워도 되는지 한 줄로 적는다(자주 묻는 질문이었다).
