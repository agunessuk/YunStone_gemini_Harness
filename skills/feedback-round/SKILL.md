# 피드백 라운드

## 언제
- "1. 2. 3." 번호를 붙인 수정 요청
- 스크린샷·화면 녹화와 함께 온 품질 지적("너무 작아", "얇아", "구려", "짜침")
- "나머지는 픽스", "이대로 확정" 같은 부분 확정

## 순서
1. **항목을 나눈다.** 번호마다 한 항목. 번호 없이 온 문장도 항목으로 쪼갠다. 첨부 영상·이미지는 프레임을 뽑아 직접 본다.
2. **확정을 먼저 기록한다.** "확정", "좋아", "이대로"인 항목은 `PROGRESS.md`의 확정된 결정에 적고 건드리지 않는다.
3. **품질 기준과 피드백 기록을 확인한다.** `docs/QUALITY_BAR.md`(규칙)와 `docs/FEEDBACK_LOG.md`(지난 지적, 없으면 새로 만듦)를 읽는다. 이번 지적을 기록에 한 줄씩 먼저 적는다. 이번 지적이 이미 기준에 있으면 **기준을 어긴 것**이므로 같은 실수를 한 다른 곳도 함께 찾는다.
4. **지적의 뜻을 넓게 읽는다.** "크게 해"는 숫자 하나가 아니라 크기·두께·유지 시간·주변 요소를 함께 보는 요청이다. "글자만 키우지 말고 박스도"처럼 이전에 같은 지적이 있었는지 기준 파일에서 확인한다.
5. **반영하고 스스로 검사한다.** 사용자에게 보내기 전에 품질 기준 항목을 하나씩 대조한다. 시각 결과는 실제로 렌더링하거나 실행해 캡처를 직접 본다.
6. **번호별로 보고한다.** 아래 형식.
7. **기준을 갱신한다.** `FEEDBACK_LOG.md`에 같은 종류의 지적이 이미 있으면(두 번째) `QUALITY_BAR.md`에 규칙으로 추가하고 기록 줄에 "→ 규칙화"를 적는다. 첫 번째 지적은 기록에만 남긴다. 규칙은 검사할 수 있게 쓴다("투사체 이펙트는 플레이어 시점에서 화면 높이의 8% 이상").

## 보고 형식
| 번호 | 요청 | 바꾼 것 | 확인 방법 | 상태 |
|---|---|---|---|---|
| 1 | 창술사 찌르기 창 제거 | 창 모델 제거, 소용돌이 유지 | 인게임 평타 3타 | 반영, 인게임 미확인 |
| 2 | 아처 투사체 2~3배 | 화살 크기 2.5배, 깃털 잔상 추가 | `/classpack test archer` | 반영 |
- 표 아래: 품질 기준에 새로 추가한 규칙 한 줄(있을 때만), 사용자가 정할 것 한 줄(있을 때만).
- "뭘 했는지 모르겠다"는 말이 나오지 않게, 바꾼 것은 화면에서 보이는 변화로 쓴다.

## 품질 기준 파일 형식
```markdown
# 품질 기준 (사용자 피드백에서 굳힌 규칙)
| 규칙 | 근거 피드백 (날짜) | 검사 방법 |
|---|---|---|
| 저품질 이전 이펙트를 재활용하지 않는다 | "구린것들을 재활용하지마" (11-09) | 새 이펙트 파일만 참조하는지 grep |
```

## 하지 않는 것
- 지적받은 항목만 고치고 같은 문제가 있는 다른 항목을 그대로 두지 않는다.
- 크기·밝기 숫자만 바꾸고 끝내지 않는다. 사용자가 원하는 "느낌"을 만드는 구조를 바꾼다.
- 확정된 항목을 다른 항목 수정하다가 같이 바꾸지 않는다.
