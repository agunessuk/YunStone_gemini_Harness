# 끊긴 작업 이어가기

## 언제
- "이어서 진행해", "끊긴 작업 이어서", "작업이 멈춘거야?" 같은 말
- 사용량 한도가 풀렸다는 알림, 문맥 압축 요약으로 시작한 세션
- 다른 AI나 이전 채팅의 인계 자료를 받아 시작할 때

## 재개 순서
1. **기록을 읽는다.** `PROGRESS.md`(없으면 `.gemini/PROGRESS.md`), 압축 요약, 인계 문서 순서로 본다.
2. **실제 상태와 대조한다.** 기록에 "끝냄"이라고 적힌 단계는 산출물이 실제로 있는지, 수정 시각이 맞는지 확인한다. 기록과 파일이 다르면 파일을 믿고 기록을 고친다.
3. **중간에 끊긴 단계를 찾는다.** 반쯤 쓴 파일, 실패한 백그라운드 작업 출력, 빌드 로그 마지막 줄을 본다. 반쯤 쓴 파일은 처음부터 다시 만든다.
4. **원본을 확인한다.** 보호된 원본(`.gemini/protected.txt`)이 그대로인지 본다. 원본이 깨졌으면 진행하지 말고 알린다.
5. **한 줄로 알리고 바로 진행한다.** "J03b의 3번째 단계부터 이어갑니다" 정도만 쓰고 묻지 않는다.

## PROGRESS.md 형식
```markdown
# 진행 기록
갱신: 2026-11-13 14:20

## 목표
(한두 줄. 사용자가 한 말 그대로)

## 지금 단계
- [x] 1. ...
- [ ] 2. ... ← 진행 중 (어디까지 했는지)
- [ ] 3. ...

## 다음 할 일
1. (바로 다음 행동, 파일 경로 포함)

## 확정된 결정
- 팔라딘 이펙트 확정 (11-13)
- 

## 미확인
- 인게임 확인 안 함: ...

## 원본·보호
- input/, output/확정/, handoff/*.zip 은 수정 금지
```
- 단계를 끝낼 때마다 갱신한다. 문맥 압축은 예고 없이 오므로 끝나고 한꺼번에 쓰지 않는다.
- 사용자가 "확정", "이대로"라고 한 것은 바로 `확정된 결정`에 적는다. 다시 고치지 않는다.
- 300줄을 넘기면 끝난 단계는 한 줄씩 요약하고 `docs/진행기록_보관.md`로 옮긴다.

## 하지 않는 것
- 기억에 의존해 "아까 했던 것처럼" 진행하지 않는다. 파일을 다시 본다.
- 이미 확정된 결과물을 재개하면서 다시 만들지 않는다.
- 끊긴 이유를 길게 설명하지 않는다.
