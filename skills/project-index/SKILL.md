# 프로젝트 색인

## 언제
- 파일이 수백 개 넘는 프로젝트를 처음 받았을 때
- 세션마다 같은 폴더를 다시 훑느라 토큰이 많이 들 때
- 팀 저장소에 올리기 전 최상위 README가 필요할 때

## 만들 것
1. **최상위 `INDEX.md`** (또는 README에 같은 내용)
   - 프로젝트 한 줄 설명, 현재 단계
   - 폴더 지도: 폴더마다 한 줄 요약, 파일 수, 먼저 볼 파일
   - 자주 쓰는 명령(빌드, 서버 실행, 테스트)
   - 정본과 사본 구분: 어떤 폴더가 기준이고 어떤 것이 보관·이전 버전인지
2. **`docs/FILE_INDEX.md`** (파일이 많을 때)
   | ID | 경로 | 종류 | 한 줄 요약 | 마지막 수정 |
   |---|---|---|---|---|
   | F001 | review/gpt/harness/CLASS_DESIGN_HARNESS.md | 기준 문서 | 클래스 설계 규칙 | 11-08 |
   - ID는 폴더별 접두어 + 번호. 이후 대화와 문서에서 ID로 부른다.
   - 목록은 스크립트로 만들고(경로, 크기, 수정 시각), 요약만 직접 쓴다.
3. 시간순 작업 흐름이 필요하면 `docs/TIMELINE.md`: 날짜, 누가(GPT·Gemini·사용자), 무엇을, 결과 파일 ID.

## 순서
1. 폴더 구조와 크기를 스크립트로 잰다. 빌드 산출물·캐시·압축 해제본은 색인에서 빼고 "제외" 목록에 적는다.
2. 큰 파일은 통째로 읽지 않는다. 앞부분과 목차만 읽고 요약한다.
3. 같은 이름의 다른 버전이 있으면 어느 것이 최신·정본인지 수정 시각과 내용으로 판정해 적는다.
4. 색인을 만든 날짜를 적는다. 이후 큰 구조 변경이 있으면 색인을 갱신한다.

## 하지 않는 것
- 색인을 만들면서 파일을 옮기거나 지우지 않는다. 정리는 사용자가 따로 요청할 때.
