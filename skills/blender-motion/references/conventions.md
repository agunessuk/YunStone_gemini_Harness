# Blockbench·ModelEngine 좌표와 부호 규칙

`scripts/bbpose.py` 가 이 규칙대로 자세를 계산한다. 렌더가 이상하면 먼저 이 문서와 대조한다.

## 1. 공간
- Blockbench 모델 공간: Y 가 위, 단위 1칸 = 1/16 블록. **모델 정면은 -Z** (해골·사람형 얼굴이 -Z 쪽).
- 앞으로 나가는 위치 키프레임 = z 음수, 뒤로 물러남 = z 양수 (옆 렌더 `--side` 로 확인함: 화면 오른쪽이 앞).

## 2. 회전
- 그룹(뼈)·큐브의 기본 회전 `rotation: [x, y, z]` 은 도(degree), 오일러 순서 **ZYX** → 행렬 `Rz · Ry · Rx`, 기준점은 `origin`.
- 옛 큐브 형식 `rotation: {angle, axis, origin}` 은 한 축 회전.
- **애니메이션 회전 키프레임**은 화면에 보이는 값 `(x, y, z)` 이고, 기본 회전에 더할 때 **x·y 는 부호를 뒤집는다**:
  `최종 오일러 = 기본 + (−x, −y, +z)`. (Blockbench 화면과 같은 결과가 나오도록 맞춘 규칙)
- **애니메이션 위치 키프레임**은 **x 만 부호를 뒤집는다**: `이동 = (−x, +y, +z)`.
- 뼈 행렬 = 부모 행렬 · T(기준점 + 이동) · R(최종 오일러) · T(−기준점). 큐브는 여기에 자기 회전을 한 번 더.

## 3. 보간
- `linear`, `catmullrom`(앞뒤 키프레임까지 써서 부드럽게), `step`. `bezier` 는 미리보기에서 linear 로 근사.
- 키프레임 값이 molang 식(`math.sin(...)` 등)이면 미리보기에서 0 으로 본다. 인게임에서는 식대로 돈다.
- `loop`: `once`(한 번), `loop`(반복), `hold`(마지막 자세 유지 — 스킬에서 `state{...;remove=true}` 로 꺼야 함).

## 4. 파일 형식 차이
| 형식 | 뼈 정보 위치 | 처리 |
|---|---|---|
| 4.x (`meta.format_version` 4.0~4.10) | `outliner` 노드 안 (`name`, `origin`, `rotation`) | 그대로 읽음 |
| 5.0 (Blockbench 4.12 이후) | `outliner` 에는 `uuid`·`children` 만, 이름·기준점·회전은 최상위 `groups` 배열 | uuid 로 합쳐 읽음 |
- `model_format`: `free`(ModelEngine 일반), `bedrock`. bedrock 형식 모델의 부호는 아직 검증하지 않았다 → **2단계 검증 렌더를 꼭 한다.**
- 텍스처가 파일 안(`textures[].source` 의 data URI)에 없으면 렌더에 색이 안 나온다.

## 5. Blender 쪽
- 변환: Blockbench `(x, y, z)` → Blender `(x, −z, y)`, 크기 1/16. 큐브마다 메시 하나, 프레임마다 `matrix_world` 를 직접 넣는다(아마추어·스키닝 없음).
- 렌더: Workbench, 텍스처 색, 그림자, 직교 카메라. `front` = 정면 오른쪽 35° 위, `side` = +X 옆.
- Blender 는 화면 없이 `-b --factory-startup` 로 돌린다. 사용자 설정·애드온 영향 없음.

## 6. 검증 방법 (모델 계열마다 처음 한 번)
1. `make_motion.py --existing <원본> <기존 공격 동작> --side` 로 렌더한다.
2. 장면 PNG 를 보고: 무기를 들었다가 **앞으로** 휘두르는가, 옆 렌더에서 몸이 **오른쪽(앞)** 으로 나가는가.
3. 거꾸로 보이면 그 모델은 규칙이 다르다 → 새 동작을 만들기 전에 원인을 찾는다(형식, 뼈 기본 회전).
- 이 검증을 거친 모델: skeleton_warrior·archer·shaman, nocsy_chibi_tree_golem (free, 4.5·4.10 형식), ender_hammerhead (free, 네발, 덮어쓰기 동작).

## 7. ModelEngine 한계
- 큐브가 뼈에 통째로 붙어 움직인다: 뼈의 **회전·이동·크기**만. 메시 변형(피부가 휘는 것)·셰이프키는 못 넘어간다.
- 뼈 이름 앞머리(`h_` 머리 따라가기 등)는 ModelEngine 이 특별 처리할 수 있다. 이름을 바꾸지 않는다.

## 8. 기본 자세와 덮어쓰기(override)
- 팩에 따라 **모든 동작 키에 '기본 자세' 값이 들어 있다** (예: 엔더 망치머리 — 머리 x 7.5, 꼬리 −7.5, 앞다리 (−2.5, 0, ∓5), 몸 위치 y −0.5).
  `inspect_model.py` 가 idle 0초 값이 0 이 아닌 뼈를 "기본 자세"로 보여 준다.
- 동작의 `override`:
  - `true` (덮어쓰기): 이 동작이 도는 동안 대기·걷기 동작을 더하지 않고 **통째로 덮는다**. 그래서 키에 기본 자세가 들어 있어야 자세가 맞다.
  - `false` (더하기): 다른 동작 위에 **더해진다**. 키는 0 에서 시작해 0 으로 끝나는 상대값이어야 한다.
- 새 동작은 **그 팩의 공격 동작과 같은 방식**으로 만든다:
  - 팩 공격 동작이 덮어쓰기 + 기본 자세 포함 → 설계 파일에 `REST_FROM = "idle"`, 동작마다 `override=True`.
    설계 키는 0 기준 상대값으로 쓰고, `make_motion` 이 기본 자세를 더하고 설계에 없는 뼈도 기본 자세로 고정 키를 깐다.
  - 팩 공격 동작이 더하기(override 없음) → `REST_FROM` 없이 0 기준으로.
  - 기본 자세가 0 인 팩(해골 계열: 공격·피격은 덮어쓰기, idle 0초 값은 전부 0)은 `REST_FROM` 이 필요 없다.
    새 동작을 더하기로 만들어도 자세는 맞고 대기 동작의 숨쉬기가 조금 섞일 뿐이다. 미리보기와 똑같이 보이게 하려면 `override=True`.
- `pose_check` 의 "시작·끝 끊김"은 덮어쓰기 동작은 기본 자세와, 더하기 동작은 0 과 비교한다. 1 을 넘으면 켜지고 꺼질 때 튄다.
