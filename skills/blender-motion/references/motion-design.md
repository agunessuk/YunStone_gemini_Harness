# 동작 설계 요령

게임 안에서 "맞는 맛"은 박자에서 나온다. 화면보다 먼저 박자(초)를 정하고, 그다음 자세를 채운다.

## 1. 박자 틀
| 구간 | 길이 | 하는 일 |
|---|---|---|
| 준비 | 0.25~0.5초 (보스 큰 기술 1.0~1.5초) | 반대 방향으로 끌어당김. 플레이어가 "온다"를 읽는 시간 |
| 타격 | 0.1~0.2초 | 가장 빠른 구간. **판정 시각**은 이 구간 끝 (무기·몸이 다 뻗은 순간) |
| 따라가기 | 0.1~0.3초 | 관성으로 조금 더 감. 망토·꼬리·머리카락이 늦게 따라옴 |
| 복귀 | 0.3~0.6초 | 기본 자세로. 이 동안이 플레이어의 반격 틈 |
- 일반 몹 공격 전체 0.8~1.6초, 보스 패턴 1.5~2.5초. 너무 길면 답답하고 너무 짧으면 못 읽는다.
- 바닥 예고(링)가 있는 패턴은 **예고 길이 = 판정 시각**. 예: 예고 25틱 → 판정 1.25초.
- 여러 번 때리는 동작은 타격마다 준비를 짧게(0.15~0.25초) 다시 넣는다.

## 2. 무게감
- 하체부터: 앞발 x −20~−35(내딛기), 뒷발 +15~+25. 웅크림은 몸 위치 y −2~−3.
- 상체: 숙이기 chest x +15~+30, 비틀기 upper_body y ±25~45 (준비 때 반대로 감았다가 타격 때 풀기).
  몸 전체(body)를 y 로 돌리면 바닥에 디딘 발도 같이 돌아 미끄러진다(수치 검사 '발 끌림'). 조준·비틀기는 상체로 하고 발은 둔다.
- 머리는 몸과 조금 반대로(시선 고정), 타격 순간엔 대상 쪽.
- 망토·꼬리·장식은 몸보다 0.05~0.1초 늦게, 진폭은 1.5배.
- 작은(치비) 뼈대는 이동 값을 줄인다 (위치 ±1~1.5칸).

## 3. 사람형 뼈대 기준 값 (해골 계열에서 확인)
| 자세 | 값 |
|---|---|
| 팔 앞으로 수평 | arm x −80~−100 |
| 팔 머리 위 | arm x −150~−170 |
| 손목 꺾기 | wrist x −20~−65 |
| 돌진 (몸이 앞으로) | body 위치 z −6~−8, 다리 x −45~−55 |
| 뒤로 뛰기 | body 위치 z +4~+7, y +5 (공중) |
| 활 조준 | upper_body y 30, 활 팔 (−96, 17, 2), 시위 팔 (−71, −52, −28) (팩은 body y 35 지만 디딘 발이 돈다) |
| 강한 피격 (0.6초) | 0.12초에 chest x −25, h_head x −30, body 위치 z +3 → 0.6초에 0 |
- 다른 모델은 기존 동작 키 값을 먼저 본다 (`inspect_model.py --json`, 또는 기존 attack 키프레임). 그 값이 그 뼈대의 "말투"다.

## 4. 이름
- 영어 소문자 snake_case: `attack_combo`, `shield_bash`, `lunge_slash`, `root_slam`, `curse_cast`, `hit_heavy`.
- 같은 역할은 모델이 달라도 같은 이름 (`hit_heavy`, `summon`) → 스킬 한 줄을 여러 몹에 그대로 쓴다.
- 원본에 있는 이름은 쓰지 않는다 (make_motion 이 막는다).

## 5. 미리보기 확인표
- [ ] 판정 프레임(빨간 테두리)에서 무기·몸이 타격 방향으로 다 뻗었다
- [ ] 준비 자세가 반대 방향이라 "온다"가 읽힌다
- [ ] 관절이 뒤로 꺾이거나 몸을 뚫지 않는다 (특히 손목·무릎)
- [ ] 옆 렌더(`--side`)에서 앞으로 나가야 할 동작이 앞(오른쪽)으로 나간다
- [ ] 마지막 프레임이 기본 자세와 같다 (끊김 없이 idle 로 돌아감)
- [ ] 정면 렌더에서 가려진 팔은 옆 렌더로 다시 본다

## 6. 네발·짐승형 뼈대 (엔더 망치머리에서 배운 것)
- 앞다리가 몸통(upper_body 등)의 **자식**이면 몸통을 돌리는 만큼 앞발이 끌려간다 → 몸통 회전과 반대로 앞다리를 보정한다.
- 다리가 큐브 하나면 무릎을 굽힐 수 없다. 웅크림은 다리를 **벌려서** 표현해야 바닥을 덜 뚫는다. 다리를 기울이면 발뒤꿈치가 바닥을 파고든다.
- 휘두르기처럼 좌우로 움직이는 동작은 `--top`(위 시점)으로 방향을 본다. 정면 3/4 만으로는 좌우를 판단하기 어렵다.

## 7. 숫자로 확인 (렌더로 잘 안 보이는 것)
`make_motion` 이 동작표.md 에 수치 검사를 적는다 (`scripts/pose_check.py`). 몸을 비틀고 발을 내딛는 동작은 팩 원래 동작도 값이 크므로,
**팩 원래 공격 동작과 비교해서** 판단한다: 설계 파일의 `COMPARE`, 없으면 이름으로 찾은 첫 공격 계열 동작.
| 항목 | 좋음 기준 |
|---|---|
| 바닥 아래 (무기 끝 포함) | 팩 원래 동작보다 1칸 넘게 깊지 않음 (기준 동작이 없으면 −1.5 칸까지) |
| 몸 이동 (맨 위 뼈 기준점) | 4 칸 이하, 또는 팩 원래 동작 +1 칸 (돌진·밀려남은 실제 이동을 `lunge` 에 맡기고 동작 속 이동은 작게) |
| 발 끌림 (몸 이동을 뺀 값) | 2 칸 이하, 또는 팩 원래 동작의 1.5 배 |
| 시작·끝 끊김 | 1 이하 (도·칸) |
- 바닥 아래는 무기 끝도 센다. 내려찍기에서 칼끝이 바닥을 깊게 뚫으면 여기 걸린다 (팩 원래 동작과 비교해 판단).
- 몸통끼리 겹침(머리가 앞다리를 뚫음 등)은 아직 숫자로 재지 않는다. 장면 PNG 를 크게 보고 확인한다.
