# 1층 공통 규칙 (어떤 스타일이든 지킨다)

스타일과 상관없이 "같은 게임의 몹"으로 보이고 서버에서 안 깨지게 하는 규칙. `lint.py` 가 `[엔진]`·`[공통]` 표시로 검사한다.
값은 스킬 기본값(`scripts/standard.py` 의 `COMMON`)이고, 프로젝트 기준 파일의 `"common"` 에 바꿀 값만 적으면 덮어쓴다.
근거: Blockbench Minecraft Style Guide, Faithful 가이드, ModelEngine 공식 위키, 보유 몹·보스 67종 수치 조사(2026-11).

## 1. 엔진 (`[엔진]`, 자세한 것은 engine-rules.md)
- Generic Model(`free`) 형식, 메시 없음, 텍스처는 파일 안에·2의 거듭제곱
- 큐브 회전은 한 축 0·±22.5·±45, 태그 뼈(`l_`·`ir_`·`seg_`…)에는 큐브 없음, hitbox 규칙, Bezier 는 linear 로 재생

## 2. 텍셀 밀도는 프로젝트에 하나
| 키 | 기본값 | 뜻 |
|---|---|---|
| `base_px_per_block` | 16 | 인게임 1블록 = 텍스처 몇 픽셀 (바닐라 16x). 32x 서버면 32 |
| `density_warn` / `density_fail` | 0.10 / 0.25 | 기준에서 ±10% 넘으면 경고, ±25% 넘으면 "확 다름" |
| `mixel_share_max` | 0.10 | 한 모델 안에서 밀도가 중앙값 ±25% 밖인 넓이 비율 (믹셀) |
| `frac_cube_share_max` | 0.10 | 소수 크기 큐브 비율 (UV 를 편 뒤 통째 확대·축소한 흔적) |
- 인게임 밀도 = 파일 밀도 × 16 ÷ MythicMobs `model{scale=}`. 무작위 배율도 0.9~1.1 안에서.
- 픽셀 크기는 스타일이 아니다: 스타일이 달라도 한 서버 안에서는 같아야 한다(플레이어가 가장 먼저 알아챔).

## 3. 형태 위생
- 같은 평면·같은 방향으로 겹치는 면 (인게임 깜박임) — 다른 뼈의 큐브라도 기본 자세에서 겹치면 깜박인다.
  원래 팩 모델은 넓이 합 `overlap_area_warn`(16px²) 이상이면 경고(작은 것은 다른 큐브에 가려 안 보이는 경우가 많다).
  **부품 보강이 새로 만든 겹침은 0** (`make_detail.py` 가 "[새 겹침]" 으로 따로 센다)
- 뒤집힌 큐브(from>to)는 표시하고 큐브 수에서 뺀다
- 새 부품은 정수 좌표, 기존 뼈에 (렌더 뼈 = 디스플레이 엔티티 수 유지)

## 4. 색 위생
| 키 | 기본값 | 뜻 |
|---|---|---|
| `unique_colors_max` | 64 | 고유 색이 이보다 많으면 부드러운 그라데이션·사진 질감 의심 (픽셀아트가 아님) |
| `colors95_max` | 24 | 픽셀 95% 를 덮는 색 수 상한 |
| `black_share_max` | 0.05 | 거의 순흑(명도 < 0.04) 픽셀 비율. 눈구멍·입 안(해골 2~3%)은 정상, 넓은 검정 면만 잡는다. 그림자는 재질의 어두운 색으로 |
| `val_min` | 0.25 | 평균 명도 하한 — 어두운 테마 몹도 어두운 던전에서 읽혀야 한다 |
| `body_textures_max` | 2 | 본체 1장 + 발광(`_e`) 1장 |

발광 짝 텍스처: 많은 팩이 `X.png` 옆에 `X_e.png` 를 둔다(면이 직접 쓰지 않는 OptiFine 식 발광 층, 본체와 픽셀 배치가 같다).
본체의 UV 배치를 바꾸는 작업(밀도 맞추기)은 짝도 똑같이 옮겨야 빛나는 자리가 어긋나지 않는다 — `density_fix.py` 는 자동으로 한다.
색만 바꾸는 다시 칠하기, 빈 곳에 부품을 넣는 보강은 배치를 안 바꾸므로 괜찮다(새 부품은 빛나지 않는다).

## 5. 성능 예산 (렌더 뼈 = 큐브가 든 뼈 = 디스플레이 엔티티 1개)
`render_bones`: 일반 24, 정예 32, 보스 96, 소환 16 — 공식 수치가 없다. 보유 몹 47종의 역할별 분포(일반 중앙 12·상위 25% 20,
보스 중앙 58·상위 25% 85)에서 이상치만 걸리게 잡은 값(처음 잡은 12·25·50 은 기준 몹 해골 전사(20)도 걸려 의미가 없었다).
몹 하나보다 **방 하나에 동시에 나오는 몹 수 × 렌더 뼈 합**이 중요하다 — 저사양 기준 수백 개(200~300) 안팎으로 설계한다.
역할은 기준 파일 `assign` 이나 `--role` 로. 소환 몹은 여럿 나오므로 예산이 작다.

## 6. 예외
- 규칙을 일부러 어기는 몹은 기준 파일 `"exceptions": {"<모델ID>": {"<규칙 키>": "이유·승인자·날짜"}}` 에 적는다.
  예외 항목은 경고가 아니라 정보로 내려간다. 같은 예외가 같은 이유로만 반복되게(Faithful 방식).
- 흔한 예외: 키 10블록이 넘는 레이드 보스의 밀도(`px_per_block`, 8 이상까지), 거대 보스 텍스처 크기.
