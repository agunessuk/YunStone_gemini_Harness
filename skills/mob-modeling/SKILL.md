# 몹 모델 스타일 맞추기·디테일 살리기 (ModelEngine)

흐름: **기준 정하기(1층 공통 + 2층 스타일 프로필) → 검사 → 라인업으로 차이 보기 → 처방 → (밀도 맞추기) → (다시 칠하기)
→ (부품 보강) → 다시 검사·라인업·동작 확인 → 사람 승인**. 모든 단계가 스크립트라 같은 입력에서 같은 결과가 나오고,
원본은 읽기만 한다. 어느 서버·프로젝트에서도 쓰도록 기준은 프로젝트 파일에 두고 스킬에는 공통 규칙만 있다.

## 기준은 2층이다
| 층 | 무엇 | 어디에 | 검사 표시 |
|---|---|---|---|
| 1층 공통 규칙 | 엔진 규칙, 텍셀 밀도 하나, 믹셀·겹침·소수 크기, 색 위생(그라데이션·순흑), 어두운 곳 가독성, 렌더 뼈 예산 | 스킬 기본값 + 프로젝트 `common` 으로 조정 | `[엔진]` `[공통]` |
| 2층 스타일 프로필 | 명도·채도·명암 폭·노이즈·테두리·위 밝음·색 수·큐브 밀도의 범위 | 프로젝트 기준 파일 `profiles` (기준 몹에서 `make_profile.py`) | `[스타일 이름·역할·테마]` |
- 프로필은 여러 개 둘 수 있다(권장 2~3). **한 화면에 같이 나오는 몹(던전 하나)은 한 프로필**, 픽셀 크기는 프로필이 달라도 같다.
- 기준 파일 찾기: `--std` → `MOB_MODELING_STD` → `작업/모델링/기준.json` → `modeling/art_standard.json` → `art_standard.json`
  → 스킬 템플릿(1층만). 작업 폴더는 기준 파일 `paths.work`(없으면 `modeling`). → `references/common-rules.md`, `references/style-profiles.md`

## 준비
- 스크립트: `scripts/` — `lint.py`(검사), `metrics.py`(수치), `make_profile.py`(프로필·몹 지정), `lineup.py`(라인업),
  `density_fix.py`(밀도), `reshade.py`(다시 칠하기), `make_detail.py`+`kitbash.py`(부품 보강). 실행은 `python -I <스킬>/scripts/…`, 현재 폴더는 프로젝트 루트.
- **blender-motion 스킬이 함께 설치돼 있어야 한다**(뼈 자세 계산, Blender 찾기). Python 3 + numpy + Pillow, Blender 4.x.
- 모델은 경로나 모델 ID(파일 이름)로 준다: `<ID 또는 경로>[@MythicMobs 배율][=이름표]`. ID 는 기준 파일 `paths.models` → 현재 폴더 아래에서 찾는다.

## 순서
0. **기준 정하기 (프로젝트에 처음 한 번)** — 후보 몹을 `lineup.py` 로 나란히 보여 주고 사용자가 기준 몹을 고른다.
   `make_profile.py --name <프로필> [--default] <기준 몹 3개 이상>` → 몹 지정 `--assign <ID,…> [--role 보스] [--theme dark]`.
   32x 서버처럼 1층 값이 다르면 기준 파일 `"common"` 에 적는다. 기준을 안 정해도 1층 검사는 된다.
1. **검사** — `lint.py <모델…> [--profile 이름] [--role 보스] [--theme dark]` : 오류(서버에서 깨질 것)·경고(규칙 밖, 인게임 확인 필요)·
   정보(큐브·렌더 뼈·키·밀도·색). 표시로 어느 층의 지적인지 본다. 해석·성능 예산 → `references/engine-rules.md`
2. **라인업** — `lineup.py --out <작업폴더>/시험/<이름>.png --stats [--back] [--per-row 6] <기준ID=이름표> <대상…>` :
   같은 축척(1블록 = 같은 px), 마인크래프트 엔티티 조명(윗면 100%, 앞뒤 74%, 옆 50%, 아래 40%), 플레이어 키 비교, 수치.
   그림을 `read_file` 로 열어 **무엇이 다른지 말로 적는다**: 형태(큐브 밀도·실루엣) / 픽셀 크기 / 명암·테두리 / 색.
3. **처방 고르기**
   | 증상 | 처방 | 맡는 쪽 |
   |---|---|---|
   | `[공통] 텍셀 밀도` 경고, 소수 크기 큐브 많음 | 4단계 밀도 맞추기 | 코드 |
   | `[공통] 평균 명도` (어두운 던전에서 안 보임) | 5단계 다시 칠하기로 밝게 — 목표는 `lint` 의 "실효 목표" 명도 | 코드 → 사람 확인 |
   | `[스타일]` 명암 폭·테두리·명도 밖, 평평하게 채운 면 | 5단계 다시 칠하기 | 코드 → 사람 확인 |
   | `[스타일] 색95` 밖 | 많으면 재질 수·계단(steps)을 줄이거나 `material(palette=…)` 로 원본 색 재사용, 적으면 부품 재질 추가 | 코드 |
   | `[스타일] 채도` 밖 | 부품 재질을 저채도로 고르고, 다시 칠하기에 `--sat <목표>` (adjust 는 어두운 곳 채도를 조금 올린다) | 코드 |
   | `[스타일] 큐브/키` 밖, 실루엣이 약함 | 6단계 부품 보강 | 코드 초안 → 사람 판정 |
   | 얼굴·문양·표면 그림 자체가 부족 | 컨셉·재질 견본은 GPT, 마감은 사람 (`references/gpt-concept.md`) | GPT·사람 |
   | `[엔진]` 태그 뼈 충돌, 회전 규칙 밖, 2의 거듭제곱 아님 | 사용자에게 보고 → 인게임 확인 뒤 결정 | 사용자 |
4. **밀도 맞추기** — `density_fix.py <원본> <출력> [--scale s]` : 촘촘하면 면마다 1 px/유닛으로 다시 깔고(원래 색만 씀),
   굵으면 정수배 확대만 한다(이어서 5단계로 1px 구조를 얹거나 사람이 다시 그림). 정수배로 안 맞는 어긋남(1.2~1.8배)은 멈추고
   다시 그리기·예외를 안내한다. 발광 짝 텍스처(`X_e.png`)는 본체와 같은 배치로 함께 옮긴다. 라인업으로 확인.
   2의 거듭제곱이 아닌 텍스처는 `density_fix.py --pow2 <원본> <출력>` (캔버스만 늘리고 UV 단위를 같이 늘려 모습 그대로)
5. **다시 칠하기** — `reshade.py <원본> <출력> --val <명도> --contrast <명암 폭> [--protect #상징색,…]` : 목표는 그 몹 프로필 범위 안.
   기본 `adjust` 는 **원래 색상을 두고 밝기 위주로** 바꾼다(대비, 1px 테두리 한 칸 어둡게, 위 밝게, 가운데 살짝 밝게, 약한 얼룩.
   어두워지는 곳은 채도가 조금 오르고 밝아지는 곳은 조금 내려간다 → 채도 목표가 있으면 `--sat`). 던전 테마 색으로 당기려면 `--tint #hex:0.2`.
   `--mode ramp` 는 새 색 계단으로 다시 칠해 색이 바뀔 수 있다 → 단조로운 텍스처(색95 ≤ 6 또는 명암 폭 < 0.08)에만, 렌더로 꼭 확인.
   **상징색(호박 주황, 눈빛, 보석)이 바뀌었으면 실패** → `--protect` 로 지키고 다시.
6. **부품 보강** — `templates/detail_spec_example.py` 를 `<작업폴더>/설계/<모델ID>.py` 로 복사해 채우고 `make_detail.py <설계.py>`.
   - 설계 전에: 뼈 트리(부모·자식 관계), 동작 범위, 기존 큐브 좌표(`print(kit.cubes("뼈"))`), 원본 색(`print(kit.colors())`)을
     본다 → `references/detail-design.md`. 설계 변수: `SRC` `OUT` `RESHADE`(mode·protect 도) `SCALE` `PROFILE` `ROLE` `THEME` `STD`
     `COMPARE`(ID=이름표, 같은 프로필 기준 몹) `LABEL` `PPB` `ANIMS`
   - **먼저 `--no-render`** (1초): 수치와 "[새 겹침]" 경고를 본다. **새 겹침 0** 이 될 때까지 좌표를 고친다.
     이때 결과는 `미리보기/<이름>/초안.bbmodel`·`보고표_초안.md` 에만 쓴다(납품본 OUT 은 렌더해서 본 판만).
   - 그다음 렌더: 라인업 v<N>(원본·직전 판·이번 판·기준 몹 — 앞·뒤 줄, 어두운 프로필이면 조명 50% 줄) + 확대 그림(원본·이번 판만 크게)
     + 동작 자세 시트(고른 다섯 순간 + 크기 키 순간, 3/4·옆) + `보고표.md`(수치·재질별 픽셀·색 수·색 예산). GIF 는 `--gif`.
     발광 짝 텍스처(`X_e`)는 그림에서도 밝게 더해져 OptiFine 에서 빛나는 곳이 보인다.
   - 프로필의 칠하기 묶음(`paint`: 테두리·가운데 밝게·결·위아래 밝기차·색상 이동)이 부품과 다시 칠하기의 기본값이 된다.
     평면 스타일 프로필이면 부품도 테두리 없이 평평하게 칠해진다. 몹마다 바꾸려면 `kit.defaults(…)`.
   - 실루엣이 먼저다: 두건·뿔·어깨·소매·치마·무기·등불처럼 멀리서 읽히는 덩어리부터. 큐브 수 자체가 목표가 아니다.
   - PNG 를 `read_file` 로 열어 본다(필요하면 잘라서 확대). 2~4번 고치는 것이 보통이다(설계만 고쳐 다시 실행, 판은 v1, v2 … 로 남는다).
7. **승인·보고** — 라인업 PNG·동작 자세 시트·보고표를 사용자에게 보낸다. "수치·렌더로 확인"과 "인게임 미확인"을 나눠 적는다.
   사람이 고칠 것(얼굴 픽셀, 문양)은 면 단위 목록으로 넘긴다.
8. **서버 적용**은 사용자 지시 때만: blueprints 원본 백업 → 복사본으로 교체 → `/meg reload` → (ItemsAdder) `/iazip` → 인게임 라인업 확인.

## 맡는 쪽 (`references/research-summary.md`)
- **코드**: 잴 수 있는 일 — 검사, 밀도, 명암·테두리 규칙, 부품 큐브 배치, 라인업·동작 렌더, 보고표.
- **사람**: 기준 몹 고르기, 실루엣·비례 판정, 얼굴·문양 마감, 라인업 최종 승인, 예외 승인.
- **GPT**: 정면·측면·후면 컨셉 시트, 재질 견본. 픽셀 격자·팔레트는 코드가 다시 맞춘다. 커스텀 몹 UV 텍스처를 통째로 맡기지 않는다.

## 지킬 것
- 원본 .bbmodel 은 고치지 않는다. 모든 스크립트가 출력 = 원본이면 멈춘다.
- 기존 뼈 이름·동작 이름·모델 ID 를 바꾸지 않는다(서버 설정·코드가 부를 수 있다). 태그 충돌 경고가 나도 이름 변경은 사용자 결정.
- 새 큐브는 크기 정수, 위치는 정수 또는 그 뼈의 기존 격자(예: .5 — 몸 픽셀과 반 칸 어긋나지 않게), 회전은 한 축 0·±22.5·±45,
  **기존 뼈에 붙인다**(렌더 뼈 = 디스플레이 엔티티 수가 늘지 않고 기존 동작이 그대로 따라온다).
- 새 면이 기존 면과 같은 평면·같은 방향으로 겹치면 인게임에서 깜박인다 → "같은 평면에 겹친 면"을 0 으로.
- 부품 면은 원본 텍스처의 연속된 빈 영역에 1px 간격으로 모인다(장수 유지, 번짐 방지). 원본 밀도가 0.5·1·2·4 px/유닛에서 벗어나면 `density_fix` 먼저.
- 빛나는 부품(`glow`)은 발광 짝 텍스처(`X_e.png`)에도 칠해진다 — 팩의 다른 발광 부위처럼 OptiFine 에서 빛난다(인게임 확인 필요).
- 다시 칠하기·밀도 결과는 렌더로 확인한다. 수치가 기준 안이어도 보기 나쁘면 실패다.
- 코드로 그린 얼굴·문양·아이콘은 품질이 낮다고 판정된 적이 있다 → 코드는 구조 음영과 부품 형태까지, 그림은 GPT·사람.
- 프로필을 늘리기 전에 테마로 안 되는지 본다. 기준이 많으면 기준이 없는 것과 같다.
- 인게임 확인 전에는 "완료"라고 하지 않는다.
