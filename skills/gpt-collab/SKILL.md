# GPT와 나눠 하기

FOD-skills `multi-ai-review`, `codex-delegation`의 채택 필터 개념을 가져와, 이 사용자의 분담 방식(그림은 GPT, 구현은 Gemini, 판정은 사용자)에 맞췄다.

## 분담 기본값
| 일 | 담당 |
|---|---|
| 아이콘·도트·컨셉아트·질감 시안 | GPT (이미지 생성). Claude가 코드로 그린 아이콘은 품질이 낮다고 판정됨 |
| 그림을 게임·문서에 연결, 구현, 빌드 | Gemini |
| 설계 검수, 명세 카드 작성 | GPT 또는 Gemini (사용자가 지정) |
| 시안 선택, 확정 | 사용자 |

## GPT에게 그림 맡기기
1. 필요한 그림 목록을 만든다: 이름, 용도, 크기(px), 배경(투명), 개수, 스타일 기준.
2. 프롬프트 파일을 만든다(`prompts/gpt/<주제>_YYYYMMDD.md`). 한 파일에 여러 장을 묶되 장마다 번호를 단다.
3. 프롬프트에 넣을 것:
   - 결과물이 쓰일 곳(예: 마인크래프트 리소스팩 32×32 스킬 아이콘)
   - 색·형태 기준, 같은 세트끼리 통일할 것, 서로 구별할 것
   - 출력 형식: 투명 PNG, 파일 이름 규칙, 한 장에 하나
   - 참고 이미지가 있으면 경로
4. **채팅 본문에도 텍스트로 붙이고** 파일도 보낸다(Remote Control에서 파일이 안 열린 적이 있음).
5. 받을 위치를 정해 알린다: `input/gpt/<주제>-vN/` (받은 결과는 원본이라 보호된다. 가공은 `work/`에서). 사용자가 결과를 넣으면 그 폴더를 읽어 적용한다.
6. 코드로 만들기 어려운 이펙트는 작업 기록에 "GPT 그림 필요"로 표시하고 사용자에게 요청한다. 혼자 낮은 품질로 채우지 않는다.

## GPT 결과 받아 반영하기
- 그림: 크기·투명도·파일 이름을 검사하고, 실제 사용 화면에서 캡처해 본 뒤 보고한다.
- 명세·검수 카드(SPEC, ACCEPTANCE): 카드 하나씩 처리한다. 카드에 없는 범위는 건드리지 않는다. 카드는 `input/gpt/cards/`에 두고, 결과는 `review/gemini/<카드이름>_RESULT.md`에 쓴다.
- GPT 검수 의견은 그대로 따르지 않는다. 채택 전 확인:
  - 지적한 문제가 실제 파일에서 재현되는가
  - 요청 범위와 확정된 결정을 바꾸지 않는가
  - 근거(파일 위치, 수치)가 있는가
  채택하지 않은 의견은 이유와 함께 결과 파일에 남긴다.

## Gemini 결과를 GPT 검수용으로 넘기기
- `handoff-pack` 스킬 형식을 따른다. 검수 요청에는 "수정하지 말고 반례와 결함만 찾아라"를 넣는다.

## 시안 여러 개 만들기
- "최대한 많은 시안"을 요청받으면 스타일·색·형태를 크게 다르게 뽑는다. 비슷한 시안 여러 개는 의미가 없다.
- 시안은 번호를 붙여 한 장의 비교 시트로 보낸다.
